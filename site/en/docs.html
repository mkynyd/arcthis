Command syntax#

One format-independent syntax. There are no ZIP-specific or TAR-specific top-level commands.

grammar
arcthis <command> <archive> [entry] [options]

The default workflow is access before extraction: inspect → tree/list → stat/read → extract only what you actually need. Full extraction is always an explicit operation.

Output rules#

Strict output separation makes Arcthis safe to drive from scripts and agents.

  • stdout carries result data only. stderr carries diagnostics, warnings and progress.
  • --json makes supported commands emit machine-readable JSON; read always prints raw file contents and rejects --json.
  • JSON output and output not attached to a terminal contain no color or styling. --no-color and NO_COLOR disable color in a terminal.
  • If the program on the other end of a pipe quits early (like | head), that counts as success — arcthis read a.zip big.bin | head exits 0.
  • Non-UTF-8 filenames are flagged explicitly through path_encoding; extraction refuses these escaped paths, so files never come out with the wrong name.

Commands#

Signatures match the real CLI; descriptions come from arcthis --help.

inspectarcthis inspect <archive> [--json]

Show an archive's basic info, capabilities and risk warnings: file counts, sizes, compression ratio, and capability flags such as random_access (can jump to any file), solid (compressed as one block) and encrypted — enough for an agent to estimate what an operation will cost before running it.

listarcthis list <archive> [--json]

List the archive's files in their original order, keeping duplicates. JSON output adds a full entries array.

treearcthis tree <archive> [--json]

Display the archive's contents as a file tree. JSON output is a nested tree array; directories that only exist as part of a path carry entry: null.

statarcthis stat <archive> <entry> [--json]

Show details for one file: kind, size, compressed size, modification time, encryption, CRC-32 and a file-type guess based on its extension. A missing path returns entry_not_found; a duplicate path returns collision because it's ambiguous which one you mean.

readarcthis read <archive> <entry>

Print one file from the archive straight to stdout, without writing it to disk — so archive contents pipe directly into the tools you already use:

arcthis read source.zip src/lib.rs | rg unsafe  ·  arcthis read media.zip video.mp4 | ffprobe -i pipe:0

findarcthis find <archive> --glob <pattern> [--json]

Find files whose paths match a wildcard pattern. Only full paths are matched; file contents are never read.

greparcthis grep <archive> <literal> [--glob <pattern>] [--json]

Search file contents without extracting them. Matches literal text (no regular expressions), entirely in memory, with caps: 16 MiB per file, 10,000 matches, 1 MiB per retained line. Binary files are skipped unless you pass --binary.

hasharcthis hash <archive> <entry> [--algorithm sha256|sha512]

Compute a file's checksum. SHA-256 is the default; SHA-512 is also supported. The result is lowercase hexadecimal.

indexarcthis index <archive> [--refresh|--delete] [--dry-run]

Create, refresh, inspect or delete a persistent index of the archive's file list, speeding up later queries. Indexes are only a cache: if the archive's size or modification time changes, the index is discarded.

extractarcthis extract <archive> [entry] [--output <path>] [--dry-run]

Safely extract everything or one selected file. The full file list is checked first; output is written to a temporary location next to the destination and saved only after every file succeeds. Related flags: --dry-run, --delete-source, and exactly one of --overwrite / --skip-existing / --rename.

extract-allarcthis extract-all <directory> [--recursive] [--workers <n>]

Safely extract every supported archive found in a directory. Archives are processed in parallel with a concurrency cap, results come out in a fixed order, and --dry-run returns one structured plan per archive found.

packarcthis pack <source> --output <archive> [--dry-run]

Pack files or a directory into an archive, then verify it. A temporary archive is built next to the destination, reopened and checked file by file, and only then saved as the final result. An output path inside the source directory, or one that points at the same file as the source, is rejected.

verifyarcthis verify <archive> [--json]

Read the archive start to finish once, verifying its structure and every readable file's data. JSON output adds a verification object with verified, entries_checked and bytes_checked.

convertarcthis convert <archive> --output <archive> [--dry-run]

Convert an archive to another format: extract safely to a temporary location, then pack and verify. File paths are preserved, resource and path safety checks run before anything is written to disk, and the new archive is verified and saved before --delete-source can remove the original.

mcparcthis mcp --allow-root <path> [--allow-output-root <path>]

The default build serves a local MCP (Model Context Protocol) server over stdio, with capped resource use and protocol revision 2025-06-18. Nine read-only tools are always available; the six extract/pack/convert plan-and-execute tools appear only after you explicitly grant an output directory. Source deletion requires both --allow-source-deletion and delete_source: true.

JSON & errors#

Every successful structured response is one JSON document followed by a newline. Command-specific fields extend a shared base structure.

base structure + entry object
{
  "schema_version": "1",
  "archive": { "path": "dataset.zip", "path_lossy": false, "format": "zip" },
  "entry": {
    "archive_index": 42,        // fixed order within the archive
    "path": "train/data.csv",
    "path_encoding": "utf8",   // or "escaped_bytes" (%XX)
    "kind": "file",
    "size": 1048576,
    "compressed_size": 182341,
    "modified_time": "2026-08-27T12:00:00Z",
    "encrypted": false,
    "crc32": "c0ffee00",
    "mime_guess": "text/csv"   // extension-based, never reads content
  }
}

With --json, command errors are JSON on stderr and stdout stays empty:

machine error — stderr
{
  "schema_version": "1",
  "error": {
    "code": "entry_not_found",
    "message": "archive entry was not found",
    "details": { "entry": "README.md" }
  }
}

Stable error categories:

unsupported_format invalid_archive corrupted_archive entry_not_found permission_denied unsafe_path resource_limit password_required wrong_password collision unsupported_operation verification_failed partial_failure io_error

Safety defaults#

The short version; exact guarantees and known limits live in docs/SECURITY.md.

  • Path checks. One unified check rejects .., absolute paths, Windows drive/UNC prefixes, NUL bytes, and links that could escape the destination.
  • No automatic links or special files. Symlinks, hardlinks and special files are not restored by default.
  • All-or-nothing writes. Output is staged in a temporary location and saved only when complete; pack reopens and verifies the new archive before it appears where you asked.
  • Overlap checks. Operations that delete or overwrite first verify the source and destination aren't the same file and don't contain each other.
  • Delete-source last. --delete-source runs only after the new files are written, verified and saved; errors, interruptions and failed checks keep the source. Dry-runs never write or delete.
  • No passwords on the command line. Passwords come from --password-file only and are hidden from debug output.
